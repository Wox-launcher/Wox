# Snippets

Create and manage snippets in the Snippets plugin settings, then search them with `snip`. For a user-facing walkthrough, see the [Snippets guide](../../../../www/docs/guide/plugins/system/snippets.md). A keyword is optional and may contain printable ASCII characters, including leading or trailing spaces. The complete keyword is replaced immediately; include a trailing space or punctuation in the keyword if it should be required. Include it in the snippet text as well if it should remain after expansion. Automatic expansion is disabled until it is enabled in the plugin settings on each device.

The snippets table is synchronized as one plugin setting. Concurrent edits on different devices follow the existing whole-setting Cloud Sync conflict behavior; the automatic expansion switch remains local to each device.

Snippet text supports `{wox:date}`, `{wox:date?format=yyyy-MM-dd}`, `{wox:clipboard_text}`, and `{wox:uuid}`. Date formats use `yyyy`, `MM`, `dd`, `HH`, `mm`, and `ss` for year, month, day, hour, minute, and second. Other ASCII letters in a date format are unsupported, and the complete placeholder is left unchanged. Other placeholders remain unchanged. If clipboard text is unavailable, expansion is cancelled. Immediately pressing Backspace after an expansion attempts to restore its keyword. Windows standard edit controls support CRLF, combining accents, and joined emoji. Undo is disabled for multi-code-point graphemes in other controls because editors differ in how much one Backspace deletes.

Automatic expansion needs access to keyboard events, focus, and input injection. On macOS, grant Wox accessibility access. On Linux, Wox normally requires accessibility services to expose the focused editable control. On Hyprland, Wox can instead use the active window when the application does not expose its controls through AT-SPI. This window-only fallback cannot identify password fields or distinguish an integrated terminal from the editor; an accessible control explicitly identified as a password or non-editable remains excluded. Wayland also requires read access to the keyboard devices in `/dev/input` and write access to `/dev/uinput`; access depends on the distribution and session configuration. A background Wayland client cannot reliably observe the active layout group; KDE uses KWin's layout service, while multiple XKB layouts on other desktops are not currently supported. Focus and input-method information are not available in every application or desktop session; expansion is cancelled when the context cannot be confirmed. Password controls and input-method composition require particular care, and platform behavior must be verified in the target application.

Some expansion paths temporarily use the clipboard. On Windows, when the previous clipboard is empty or contains text, files, or an image, staging checks the original generation and restoration checks a unique marker while holding the system clipboard lock. Windows expansion is cancelled if the clipboard contains only unrecognized formats. A last check before pasting reduces but cannot eliminate a copy racing with the target application's paste. macOS and X11 use separate checks and writes, so a concurrent copy can still race with staging or restoration. Wayland clipboard ownership cannot currently be verified by this plugin, so the staged text may remain on the clipboard. Reliable conditional restoration across all supported formats and platforms remains unresolved.

On Linux, run `WOX_TEST_X11_ISOLATED=1 xvfb-run -a go test -race ./plugin/system/snippets` from `wox.core` to include the native X11 replacement test. This test injects keys into the selected X server; only set the variable for a dedicated test display.

On Windows, set `WOX_TEST_WINDOWS_INPUT_ISOLATED=1` and run `go test ./plugin/system/snippets -run TestWindowsReplacement -count=1` from `wox.core` to test injection into a temporary native edit control. This test briefly takes foreground focus and sends keyboard events; run it only when the desktop is available for the test.

Set `WOX_TEST_WINDOWS_EDITOR_ISOLATED=1` and run `go test ./plugin/system/snippets -run TestWindowsNotepadExpansion -count=1` to test Unicode and multiline replacement in a temporary Notepad document.

Set `WOX_TEST_WINDOWS_TERMINAL_ISOLATED=1` and run `go test ./plugin/system/snippets -run TestWindowsTerminalExpansion -count=1` to test multiline replacement in a new Windows Terminal window. The test injects a trigger and verifies the two lines received by a temporary console program.

To verify physical input on Windows, set `WOX_TEST_WINDOWS_MANUAL=1` and run `go test ./plugin/system/snippets -run TestWindowsManualPhysicalInput -count=1 -timeout 120s -v`. In the temporary foreground window, type `;wx` using an English keyboard layout and press Backspace after it expands. The test checks both expansion and undo and does not alter saved snippets.

Set `WOX_TEST_WINDOWS_MANUAL_MULTILINE=1` as well to test multiline paste, undo, and clipboard restoration. In this mode, type `;wx`, wait for the two-line expansion, and press Backspace; the test checks the previous clipboard content after the paste.
