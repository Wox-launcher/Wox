# Plugin logo design

Use this workflow, adapted from Icon Design, only for the plugin's identity logo in metadata. Do not use the image generator or rounded-square mask for result, action, setting, or other functional icons; prefer SVG for those as described in [icons.md](icons.md). The workflow is self-contained so Wox's bundled skill can use it without installing the Icon Design plugin. Respond in the user's language. Honor an explicit request to keep an existing or supplied logo; do not replace an existing shipping logo during unrelated edits.

## Art direction and concepts

1. Inspect the plugin's purpose, existing identity and any user-supplied visual references. Describe the plugin in one sentence and choose a literal, suggestive or abstract association appropriate to the brief. A name is context, not a requirement to draw its initials or rename anything.
2. Design an original, recognizable mark with a coherent palette, visual hierarchy and enough negative space to read at launcher sizes. For a reference, identify concrete qualities such as contour, proportions, contrast, color and depth; if the image provider supports reference images, actually provide the image when using it as a visual guide.
3. Explore a small set of distinct directions, normally 3–4 when useful. Vary the mark's silhouette and composition, not just its color or material. A concise prompt should describe the plugin purpose, association, mark, field, palette, scale and finish, with only relevant exclusions. Avoid unnecessary text, tiny detail and product mockups.
4. Use the available image-generation tool for original raster concepts, preferring the built-in `image_gen` tool and its imagegen skill when available. Do not claim a hand-coded SVG is AI-generated. If generation is unavailable, explain the limitation and use a suitable existing or intentionally authored icon if appropriate; do not silently claim generation succeeded. Follow the imagegen skill's CLI fallback and authorization rules, including any third-party endpoint or cost approval, before using an alternative provider.

## Shape and review

- The final plugin logo must be a square image with an iOS-like rounded-square tile: smooth, generous rounded corners and transparent pixels outside the tile. The tile fills the canvas and the central mark has breathing room. An approximately 22–25% corner radius is a starting point, not a claim to reproduce Apple's exact mask.
- Generate full-bleed square artwork without a baked-in rounded tile or surrounding background, then apply the mask to the final Wox asset; Wox should not be assumed to apply it. Keep the unmasked source for revisions. Run `python3 scripts/round_plugin_logo.py source.png logo.png` (use `python` if needed); it requires Pillow, defaults to 512 px and a 23% radius, preserves existing alpha and refuses to overwrite. Install Pillow in a project-local environment if needed. Optional `--size 256` and `--radius 0.24` adjust the output. The result is an iOS-like approximation, not Apple's exact mask.
- If reusing an image with an existing tile, `--crop LEFT TOP RIGHT BOTTOM` selects a square region in source pixels before masking. The mask intersects the original alpha; it cannot restore missing artwork, remove artifacts inside the mask or reliably repair an already rounded edge. Inspect the result and regenerate full-bleed artwork if necessary. A rounded tile painted onto an opaque square background does not satisfy the transparency requirement.
- Inspect the real result at 16, 24, 32 and 48 pixels on light and dark backgrounds. Check recognition, optical balance, contrast, clean corners, unwanted associations and edge halos. Refine the weakest aspect if needed. A dark surrounding is not a separate dark-mode asset.
- Save useful source images and exact prompts in the plugin project when it has one. Compare directions and explain the recommended one when useful. If the user requested a review or selection gate, wait for that selection before replacing the shipping icon; otherwise choose the strongest result and continue. Preserve an explicitly chosen direction.

## Integrate with Wox

- For a packaged SDK plugin, save the final transparent PNG inside the plugin, for example `assets/logo.png`, and set `Icon` in `plugin.json` to `relative:assets/logo.png`. Make sure the asset is included in the package.
- A single-file SDK plugin cannot rely on companion files or relative paths. Encode a suitably sized transparent PNG as a data URI and put `base64:data:image/png;base64,...` in the header's `Icon` field. Keep exploration files outside the live single-file plugin directory; only the plugin file belongs there. An explicitly requested SVG deliverable may instead be embedded with `svg:` and must preserve the rounded silhouette.
- A result may reuse the plugin logo when it represents the plugin itself; otherwise prefer a suitable SVG for the result. Action Panel icons remain separate monochrome theme-adaptive SVGs; see [icons.md](icons.md).
- Report the final asset or embedded destination, prompt and generation method, and the small-size and transparency checks actually performed. Do not claim native Apple Icon Composer validation or create `.icon` / `.icns` assets unless the user separately asks for Apple delivery.
